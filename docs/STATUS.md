## 2. 旧版 US 审查结果（本轮未重写策略）

### [P2] 子任务硬限制仍与“只节省主模型额度”冲突

位置：agents/op-lead-with-us.md:77、135–137；skills/op-lead-with-us/SKILL.md:54–56。

US 限定一次调研、默认最多两个活跃 Worker、未经扩大计划授权最多四个实现包；公共技能也继续加载这些限制。
多模块任务会因子任务数量而提前等待用户授权，不能把 README 中“不限制子模型消耗”的目标视为已实现。
建议：另行移除节省子模型调用的任务总量限制；并发只保留宿主容量、文件/资源冲突等执行约束，继续压缩主模型回报。

### [P2] 仅表达节省额度会意外进入只规划模式

位置：agents/op-lead-with-us.md:99–113。

触发条件包含“用户要求节省 Opus 额度”，但这本就是普通 US 执行模式的目标。
“帮我实现功能并节省 Opus”可能因此只得到 PLAN.md，被要求换会话而没有完成实现。
建议：只在用户明确选择 PLAN_ONLY、仅规划或两阶段交接时启用；普通节省额度请求继续完整委派执行。

### [P2] US 并发修复没有预留全局预算

位置：agents/op-lead-with-us.md:126–127；结合第 89 行的全任务两次修复限制。

每包 initially 2 与最多两个并发 Worker 可以同时成立，两个包各修两次会超过总数两次；事后收集 repair_cycles_used 无法阻止超用。
CRY 已采用“已使用 + 未结算分配 <= 5”，US 尚未迁移相同的预算预留原则。
建议：无论 US 后续选择何种修复策略，保留总预算时必须在派发前分配，不能给每个并发包复制全局余额。

## 3. 已实现功能

这里“已实现”区分指令协议与可执行脚本，不表示模型在运行时必然遵守。

| 模块 | 已有能力 | 边界 |
| --- | --- | --- |
| 双主协调员 | US 保护主模型额度；CRY 以并发增速为目标 | US 的旧限额仍待对齐 |
| 三种 Flash Worker | researcher 调研、implementer 编辑/测试、reviewer 独立审查 | flash 为档位；只读角色约束不等于系统级隔离 |
| CRY 并发协议 | 主动拆分、依赖就绪队列、并发派发、完成即补位 | 本地最多 3 个活跃 Worker，不保证预留宿主通道 |
| CRY 调用策略 | 不限制正常 Worker 派发总量；单 Worker 区间需说明依赖/资源等原因 | 不制造重复工作填槽位；容量不足时降速 |
| 写入与审查 | 路径及共享资源所有权；稳定范围可并行审查；相关写入结束后集成验证 | 提示词协议，非硬文件锁 |
| CRY 修复记账 | 全任务 5 次，派发前分配，替换不重置，未知用量保守扣除 | 非计费/Token 硬上限 |
| 两阶段规划 | PLAN_ONLY 生成不超过 120 行计划，单个执行员原文转写后停止 | US 的误触发问题见审查结果 |
| 回报压缩 | 调研/实现/审查分别最多 40/50/60 行，失败日志最多 15 行 | 控制传回主模型的上下文，不限制 Worker 执行 Token |
| 工具与路由诊断 | LEAD_TOOLCHECK、缺委派/未发现 Worker/并发不可用诊断、UNVERIFIED 状态 | 配置与模型自述不等于运行证据 |
| 安全与取消 | 不自动提交/推送/部署/越权；取消仅针对本任务且等待确认 | 依赖宿主工具与模型遵循 |
| 安装工具 | 项目内 staging、全局安装/卸载、Windows install.bat 启动器 | Windows 启动器需 Node.js 18+；本轮未运行真实全局变更 |
| 开发验证 | 静态校验、离线回归、ZIP/SHA256 打包脚本、实机冒烟指南 | 本轮不重新发布 ZIP；旧输出不代表新版本 |
